# 箱外之地 · Mini Delta Force v3

移动端优先的零号大坝搜箱撤离游戏。在线游玩：[GitHub Pages](https://tinyrattar.github.io/MiniDeltaForce/)。

## 这版怎么玩

- **搜箱**：回到原版零号大坝地点与连通路线，地点可重访，容器不会重复刷新。所有零价物品从目录和掉落表移除。首箱保底紫；连续三箱无紫后下一箱保底紫；第八个新搜刮地点首箱保底金。
- **整理**：藏品按实际尺寸占格，可旋转、手动定位、跨区移动和整理。背包为完整矩形；胸挂为独立小仓；口袋为六个独立单格；保险箱 3×3。
- **时间**：每局 30 分钟行动预算，赶路 90–120 秒，搜索 45 秒，事件按选项扣时，撤离另需 60 秒。阅读、揭晓动画、整理背包不扣时间。时间到 0 立即失败。
- **撤离**：必须赶到东部或西部撤离点。固定状态栏始终显示时间、背包空位、预计收益、生命；撤离最短时间包含接应，但不含途中随机事件。
- **生命**：初始 100。巡逻人机、背刺和高危搜索会造成伤害。流血按累计行动时间每 10 秒扣 2 生命，血量归零立即失败。
- **药品**：强效注射器回血 60，使用 8 秒；绷带止血，使用 5 秒。背包/保险箱中的药品额外花 5 秒取出。药品是有限库存，在特勤处购买并指定携带数量，也能在医疗容器或事件中获取。
- **事件**：12 种贴近大坝的遭遇，包括鼠鼠暗号馈赠与背刺、哈夫克巡逻、赛伊德、曼德尔砖信号、钓鱼盒与停火协议。危险和概率在选项中明确展示。同局不重复。
- **装备与损失**：购买的背包、胸挂不是永久升级。失败掉落本次携带的装备、非保险物品与本局零钱，仓库里的备用装备不掉。保险箱物品保留，藏品兑现，药品回库存。成功时物资全额带回，委托才支付奖金。

## 装备资料

采用用户指定的八档背包尺寸；胸挂总容量及分仓参考公开资料。市场价格只作为固定游戏售价的参考快照，D7 / GTO 使用明确标记的游戏内平衡价。参见 [装备与医疗资料来源](docs/equipment-sources.md)。

## 本地运行与验证

纯静态 HTML / CSS / ES modules，无运行依赖，无需安装 npm 包。Node.js 22+ 用于检查，CI 使用 Node.js 24。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/dev-server.ps1 -Port 4173
```

打开 `http://127.0.0.1:4173/`，不要使用 `file://`。

```sh
node --test tests/*.test.mjs
node --check src/app.js
node --check src/domain/expedition.js
node scripts/check-assets.mjs
```

有 npm 时可使用 `npm test` 和 `npm run check`。当前 32 组测试包含 500 局确定性战局模拟、库存与结算边界，以及通过模拟浏览器接口测试实际 app 模块的点击处理。模拟接口测试不等于真实浏览器布局、触屏或手机真机验证。

## 结构与数据

- `src/domain/expedition.js`：确定性战局、费用、伤害、结算、存档迁移。
- `src/domain/inventory.js`：矩形装包、旋转、碰撞和整理。
- `src/app.js`：界面、固定状态栏、装包交互、医疗与整备。
- `src/data/map.js`：原版零号大坝地点与连通关系。
- `src/data/equipment.js`：背包尺寸、胸挂分仓、固定售价与医疗配置。
- `src/data/encounters.js`：带明示成本和概率的遭遇。
- `scripts/prune-zero-value.mjs`：清除物品目录及容器池中的无效价格条目。
- `scripts/build-local-icons.mjs`：生成本地物品图片索引。没有本地图的物品使用符号，不请求外部图片。

原始抓取快照保留在 `data/` 作为历史资料；游戏不会从原始快照直接抽取物品。

## 存档与发布

v3 使用独立 localStorage 键 `mini-delta-force-expedition-v3`。首次从 v2 迁移时保留资金与已收藏物品，退款旧永久升级，并把旧局已装包物品及零钱兑现；原始 v1/v2 存档不删除。新存档不跨设备同步。

打开容器时即确定物品；事件选择后立即保存结果。刷新不重抽，结算不能重复领取。关闭页面可继续，写入失败会提示。

PR 自动运行 `Check game`；合并到 main 后，`Deploy GitHub Pages` 先验证，再发布。入口和模块导入均携带版本标记，以免浏览器混用旧版脚本。

其他 v0.1/v2 设计文档为历史记录，当前玩法以本文件和源码为准。
