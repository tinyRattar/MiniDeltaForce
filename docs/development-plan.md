# 开发计划

版本：v0.3 草案  
状态：第一版 MVP 执行计划  
更新时间：2026-06-05

## 1. 目标与范围

第一版目标不是还原完整撤离搜打游戏，而是做出一个手机端可玩的最小闭环，验证“节点移动、搜索容器、逐步揭示、随机事件、负面状态、撤离结算”是否成立。

第一版核心流程：

```text
特勤处简易准备 -> 进入战局 -> 相邻地点移动 -> 搜索容器 -> 揭示与拾取物资 -> 触发随机事件 -> 使用道具处理状态 -> 撤离或死亡 -> 结算与本地存档
```

第一版明确不做：

- 完整战斗界面与自动战斗。
- 特战干员后台移动、搜索和撤离。
- 击败敌人后的尸体 loot。
- 装备耐久、维修、复杂武器防具经济。
- 任务系统、角色等级、设施升级。
- 联网、排行榜、账号系统。

## 2. 推荐决策

策划文档中的待确认问题，第一版按以下推荐方案执行：

- 游戏模式：先做单人离线体验，所有数据保存在本地。
- 整体风格：轻硬核外壳 + 休闲策略内核，事件文本允许轻度幽默和反差感。
- 单局节奏：使用 30 分钟局内行动时间，真实游玩目标控制在 8-12 分钟。
- 技术栈：Vite + React + TypeScript。
- 状态管理：核心规则使用纯 TypeScript domain engine，UI 层用 React state/useReducer 承接；暂不引入大型状态库。
- 样式方案：原生 CSS 或 CSS Modules，优先少依赖、易部署。
- 数据格式：地图、地点、容器、物品、事件全部 JSON/TS 配置化。
- 存档：localStorage，保存仓库、货币、最近一局结算和设置。
- 背包：第一版做战局背包格子与自动放入/丢弃；物品数据支持尺寸和旋转，拖拽旋转整理延后。
- 仓库：第一版无限容量列表，不做仓库格子整理。
- 保险格：第一版保留 3x3 规则与数据结构，但 UI 可先只做简化展示。
- 胸挂：第一版不单独做胸挂格子，三种功能道具作为固定随身道具栏。
- 初始资源：固定赠送三种功能道具和少量启动资金，避免玩家首局卡死。
- 容器重开：已搜索容器允许再次查看剩余物，但不重新生成物资。
- 随机事件：第一版只在搜索后触发，基础概率 10%。
- 撤离点：先做西部撤离点、东部撤离点两个普通撤离；条件撤离后置。

## 3. 里程碑

### 阶段 0：项目骨架与数据收口

目标：建立可开发、可测试、可静态部署的基础工程。

交付：

- Vite React TypeScript 项目。
- 基础路由或页面状态：特勤处、战局、搜索、结算。
- 数据目录结构：items、map、containers、events、starter-loadout。
- 第一张地图节点与拓扑录入。
- 最小物品池录入，优先使用 `docs/item-data-v0.1.md` 中可进入 MVP 的物品。
- 容器类型与掉落池草案录入。
- ESLint/TypeScript 检查命令。

验收标准：

- 本地开发服务器可启动。
- 静态构建可成功输出。
- 地图、物品、容器数据能被 TypeScript 类型校验。

### 阶段 1：核心规则原型

目标：不依赖精美 UI，先让一局游戏在规则层跑通。

交付：

- 战局生成器：生成地图状态、容器内容、玩家状态、行动时间。
- 固定容器出货：每个容器开局生成一次并锁定。
- 节点移动规则：只能移动到相邻地点，正常消耗 2 分钟，腿骨折消耗 3 分钟。
- 搜索规则：搜索当前地点未搜索容器，消耗 1 分钟，搜索后标记已搜索。
- 搜索揭示规则：按品质决定揭示耗时，手骨折时揭示耗时延长 50%。
- 随机事件规则：搜索后 10% 概率触发事件，支持先决条件。
- 生命值规则：最大 100，伤口按经过分钟流血，最低降到 1。
- 负面效果规则：腿骨折、手骨折、伤口可重复记录，同类实际效果不叠加。
- 道具规则：强效注射剂、快拆手术包、瓶装止痛药。
- 撤离与死亡结算规则。

验收标准：

- 可以从代码或极简界面跑完一次“进入战局 -> 移动 -> 搜索 -> 拿取 -> 撤离/死亡 -> 结算”。
- 容器不会重复出货。
- 时间、生命值、负面效果和道具次数变化符合策划规则。
- 关键规则有基础单元测试。

### 阶段 2：手机端可玩 MVP

目标：把规则原型包装成手机端可玩的网页版本。

交付：

- 特勤处简易页面：显示货币、仓库摘要、开始战局按钮。
- 行前准备：默认携带 4 根强效注射剂、1 个快拆手术包、1 瓶瓶装止痛药。
- 战局主界面：地点名称、相邻地点、当前容器、撤离状态。
- 状态栏：剩余时间、生命值、负面效果、止痛药剩余时间、携带价值。
- 地图 UI：节点式地图，突出当前位置、相邻可达地点、普通撤离点。
- 容器列表：显示当前地点可搜索/已搜索容器。
- 搜索界面：物品轮廓、逐步揭示、品质颜色、价值、重量、拾取按钮。
- 背包简化 UI：格子容量、已携带物、自动放入失败提示、丢弃物品。
- 随机事件弹窗或日志：展示事件文本与结果。
- 道具栏：三个功能道具可用、次数可见、不可用时明确反馈。
- 撤离结算：带出物资、总价值、耗时、事件摘要、仓库入账。
- 死亡结算：丢失战利品，保留保险格内物品。
- localStorage 存档：仓库、货币和设置。

验收标准：

- iPhone 级窄屏宽度下能完整游玩一局。
- 不出现关键按钮被遮挡、状态文字溢出、搜索界面无法操作的问题。
- 玩家能理解当前能去哪里、能搜什么、什么时候该撤。
- 刷新页面后局外存档仍在。

### 阶段 3：内容扩展与平衡

目标：增加重复游玩的变化，补足第一版内容量。

交付：

- 补齐各地点固定容器列表。
- 为高价值区域配置更强容器组合。
- 扩展容器掉落池：保险、骇客电脑、医疗箱、工具柜、快递箱、鸟窝、窨井盖等。
- 扩展随机事件文本，至少覆盖搜索受伤、遭遇小兵、空箱吐槽、意外惊喜、环境事故。
- 调整掉落价值曲线，保证低价值物常见，高价值物有期待但不泛滥。
- 增加局后统计：搜索容器数、最高价值物、险情次数、撤离评价。

验收标准：

- 连续游玩 5 局，路线、容器收益和事件结果有明显差异。
- 高价值区域比普通区域更值得去，但不会稳定暴富。
- 负面状态和医疗道具能形成取舍，不是纯惩罚或纯装饰。

### 阶段 4：体验打磨与发布

目标：把 MVP 打磨到可以公开试玩。

交付：

- 响应式布局打磨，覆盖常见手机和桌面宽度。
- 动效与音效：搜索揭示、拾取、受伤、撤离、结算。
- 存档容错：版本号、坏档恢复、重置存档。
- 新手首局引导：用极少提示说明移动、搜索、撤离。
- PWA 基础支持：图标、manifest、离线缓存。
- GitHub Pages 部署配置与发布说明。

验收标准：

- 静态部署后可直接游玩。
- 首次进入无需说明文档也能完成一局。
- 移动端性能稳定，无明显卡顿和布局错位。

### 阶段 5：后续大系统

目标：在第一版闭环成立后，再逐步恢复复杂玩法。

候选方向：

- 完整自动战斗与战报。
- 人机与特战干员后台模拟。
- 特战干员搜索容器、带走物资、提前撤离。
- 击败敌人后的 loot。
- 手动背包拖拽、旋转、快速整理。
- 胸挂、保险格、装备栏深度整理。
- 商店、装备经济、维修与耐久。
- 任务、成就、轻量成长。
- 更多地图。

## 4. 推荐工程结构

```text
src/
  app/
    App.tsx
    routes.ts
  data/
    items.ts
    map.ts
    containers.ts
    events.ts
    starterLoadout.ts
  domain/
    types.ts
    rng.ts
    raidGenerator.ts
    movement.ts
    search.ts
    inventory.ts
    events.ts
    health.ts
    items.ts
    extraction.ts
    settlement.ts
    save.ts
  ui/
    components/
    screens/
  styles/
  tests/
```

工程原则：

- `domain/` 不依赖 React，便于测试和后续迁移。
- `data/` 只放配置，不写业务流程。
- UI 层只负责展示和调用 domain action。
- 随机数使用可注入 seed，方便复现问题。
- 存档要带版本号，后续数据结构变化时可迁移。

## 6. 风险与控制

- 背包交互容易拖慢第一版：先做自动放入和丢弃，拖拽整理后置。
- 数据量容易失控：第一版只选 MVP 物品池，后续再补真实数据。
- 随机事件容易变成纯惩罚：事件结果要混合无伤、轻伤、状态、惊喜和幽默文本。
- 数值过大影响可读性：UI 中金额使用短格式，例如 `13.1M`、`92.3K`。
- 搜索节奏可能拖沓：揭示时间按品质执行，但允许已揭示物立即拾取。
- 本地存档可能坏档：存档带版本号并提供重置入口。

## 7. 完成定义

第一版完成时，必须满足：

- 玩家能在手机浏览器中从特勤处开始并完成一局。
- 至少有一张完整节点地图。
- 至少有 8 类容器和一批可拾取物品。
- 搜索揭示、随机事件、负面状态、道具、撤离结算都真实生效。
- 成功撤离能把物资写入仓库。
- 死亡会丢失战局物资。
- 刷新页面后局外存档保留。
- 项目可以静态构建并部署。
