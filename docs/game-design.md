# 网页端撤离搜打小游戏策划案

版本：v0.1 草案  
状态：逐章节核对中  
更新时间：2026-06-05

## 0. 文档说明

本文档用于沉淀网页端撤离搜打小游戏的策划案。后续讨论采用“逐章节核对”的方式推进：每一章先列出当前建议、已确认结论与待确认问题；与你确认后，再更新为正式设计。

本文档不会直接复刻任何现有商业游戏的名称、地图、美术、装备命名或 UI 表现，而是借鉴“搜索、交战、撤离、带出、整备”的类型体验，形成原创网页小游戏方案。

## 1. 产品定位

### 1.1 当前建议

游戏定位为移动端优先的网页小游戏，核心体验是图形化节点地图 + 文本事件 + 背包管理 + 简化战斗。

玩家在局外进行行前备战，进入单次战局后，在有限时间内选择目标地点、搜索容器、处理随机事件、与敌人交战，并判断撤离时机。成功撤离后带出物资，回到局外出售、留用或继续备战。

整体调性不追求强压迫感或硬核惩罚，而是保留撤离搜打的熟悉结构，做成轻松、有取舍、偶尔让玩家会心一笑的小型策略体验。时间限制和撤离风险主要用于制造节奏与选择，不应让玩家长期处在高压力状态。

### 1.2 已确认

- 游戏需要适配手机端运行。
- 游戏主要包含两个阶段：特勤处与战局。
- 游戏体验核心是“搜打撤”：搜索、交战、撤离。
- 表现形式倾向于图形化节点地图 + 文本事件 + 背包管理，而不是纯文字策略模拟。
- 游戏后台需要保存战局隐藏状态，避免容器重复出货、敌人数量突破地图上限等逻辑问题。
- 游戏不需要太强的撤离压力，重点是轻松、有趣、有策略取舍，并能让熟悉同类玩法的玩家会心一笑。

### 1.3 待确认

- 游戏是否只做单人离线体验，还是未来考虑弱联网、排行榜或异步玩家影子？
- 游戏整体风格暂定为轻硬核外壳、休闲策略内核；是否加入更明显的戏谑文本与轻喜剧事件？
- 单局平均时长目标暂定为 8-12 分钟；是否需要支持 3-5 分钟的快速局？

## 2. 核心循环

### 2.1 当前建议

核心循环如下：

```text
特勤处整备 -> 进入战局 -> 选择目标地点 -> 移动/搜索/遭遇 -> 战斗或规避 -> 撤离或阵亡 -> 结算 -> 回到特勤处
```

局外循环强调资源积累、装备取舍与行前准备；局内循环强调自由搜刮、路线选择、背包摆放、风险收益判断与撤离决策。

初版不设置主要任务目标，玩家进入战局后的主要动机是自由搜索、获得物资、尽量带出更有价值的战利品。游戏可以保留“顺手达成”的轻量成就或委托，但它不应成为单局主线。

地图地点在开局时就是确定且可见的，每个地点有哪些容器也对玩家可见。玩家需要根据地点风险、容器类型、距离、剩余时间和自身装备决定路线。

背包管理是核心体验之一。背包格子有限，物品有不同占格形状或尺寸，玩家需要花一些心思进行摆放和取舍，以尽可能还原原型游戏中“这个也想带、那个也舍不得”的整理体验。手机端交互需要为拖拽、旋转、快速整理和丢弃提供顺手操作。

### 2.2 已确认

- 玩家需要在特勤处进行行前备战。
- 玩家需要在战局中选择前往目标地点。
- 前往目标区域和搜索后都可能触发随机事件。
- 搜索目标区域需要有固定容器与固定产物逻辑。
- 单次对局中的对手数量应在进入对局时确定。
- 初版不需要主要任务目标，战局以自由搜刮和带出物资为主。
- 地图地点是确定且可见的。
- 每个地点有哪些容器是确定且可见的。
- 背包管理比较重要，需要有限格子与手动摆放，尽量还原同类游戏的整理取舍体验。

### 2.3 待确认

- 背包物品是否支持旋转？
- 背包整理是否允许一键整理，还是完全依赖玩家手动摆放？
- 是否允许中途主动丢弃部分物资以换取更高移动效率？
- 未来版本是否加入轻量委托或成就，但不作为单局主要目标？

## 3. 特勤处

### 3.1 当前建议

特勤处是局外准备与成长界面，初版包含：

- 仓库
- 背包整理
- 装备栏
- 商店
- 出售物资
- 行前备战
- 开始战局
- 保险格

装备栏建议包括：

- 主武器
- 副武器
- 头盔
- 护甲
- 胸挂
- 背包
- 药品
- 投掷物
- 弹药或补给

初版保险格为 3x3。玩家可以在行前把少量高价值物品或关键物资放入保险格。角色在战局中阵亡时，普通装备、背包和战利品全部丢失，但保险格内物品保留。

商店采用固定售卖列表，提供基础武器、防具、胸挂、背包和消耗品，不做每局随机刷新。这样玩家能稳定完成行前备战，减少局外挫败感。

仓库初版不做格子限制，视为无限容量列表或分类仓库。背包摆放压力主要集中在战局背包、胸挂与保险格，避免局外整理过重。

### 3.2 已确认

- 特勤处中可以进行行前备战。
- 特勤处中可以购买武器、防具、胸挂、背包和消耗品。
- 初版需要保险格，尺寸为 3x3。
- 战局阵亡后普通装备、背包和战利品全部丢失，保险格物品保留。
- 商店固定售卖基础物品，不做随机刷新。
- 仓库初版无限制，不做格子摆放。

### 3.3 待确认

- 初版是否需要设施升级，例如仓库扩容、商店等级、医疗恢复？
- 保险格是否允许放入战局中搜到的任意小件物品，还是限制某些类型？
- 胸挂是否也使用格子系统，还是作为快捷消耗品栏？
- 初始赠送装备与资金是多少？

## 4. 战局结构

### 4.1 当前建议

进入战局时，系统生成并保存一份完整的战局状态：

- 地图节点
- 敌人总数、类型、位置与状态
- 每个容器的固定内容
- 撤离点状态
- 随机事件池
- 当前时间与时间限制
- 玩家当前位置、状态、携带物

玩家不需要始终知道全部信息，但系统必须在后台持有这些信息，保证规则一致。

时间系统采用回合制行动时间，而不使用真实倒计时。移动、搜索、战斗、治疗和撤离都会消耗若干分钟。这样玩家可以在手机端从容思考，同时保留“时间正在减少”的撤离感。

敌人分为两类：

- 人机：主要作为区域威胁存在，可固定驻守或在特定事件中出现。
- 特战干员：作为同局竞争者存在，会在后台移动，甚至搜索容器并带走物资。

特战干员拥有自己的状态：

- 当前所在地点
- 装备
- 背包与已搜到物资
- 行动计划或目标倾向
- 生命状态

当玩家遭遇并击败特战干员时，可以 loot 其本身携带的装备，以及其在本局中已经搜索到的物资。特战干员搜索过的容器会被标记为已搜索或部分搜索，玩家之后再去该容器时不能重复获得同一批物资。

撤离点在开局全部可见，但敌人总数、敌人位置、敌人剩余数量和特战干员行动状态对玩家完全不可见。玩家只能通过事件文本、声音提示、已被翻过的容器、远处交火等间接信息进行判断。

### 4.2 已确认

- 游戏需要时间限制。
- 容器中的产物固定。
- 单次对局中的对手数量在进入对局时确定。
- 后台需要存储必要信息，避免不合理重复生成。
- 时间限制采用回合制行动时间，不使用真实倒计时。
- 敌人分为人机和特战干员。
- 特战干员会在后台移动，并且可以搜索容器、携带搜到的物资。
- 击败特战干员后，可以搜刮其装备和已获得物资。
- 撤离点开局全部可见。
- 当前地图剩余敌人数量对玩家完全不可见。

### 4.3 待确认

- 人机是否也会移动，还是初版主要固定驻守？
- 特战干员数量范围是多少？
- 特战干员是否可以与人机交战，并改变地图状态？
- 特战干员是否可能提前撤离，带走其搜到的物资？

## 5. 地图与目标地点

### 5.1 当前建议

初版使用节点式地图。每张地图由若干地点构成，玩家只能前往当前地点的相邻地点。节点之间存在拓扑关系图，但第一版所有相邻移动的耗时暂时相同。

每个地点包含：

- 地点名称
- 风险等级
- 物资类型
- 容器列表
- 敌人/事件概率
- 可连接地点
- 是否为撤离点或任务点

第一张地图参考“零号大坝”的空间布局与搜打撤节奏，地点先包括：

- 西部撤离点
- 水泥厂
- 建筑工地
- 军营
- 河滩
- 行政楼西楼
- 行政楼东楼
- 集装箱
- 坝体内部
- 停车场
- 坝顶
- 养护站
- 主变电站
- 备用变电站
- 游客中心
- 东部撤离点
- 管道区域

撤离点设计：

- 西部撤离点：普通撤离点。
- 东部撤离点：普通撤离点。
- 河滩：存在付费撤离点，但第一版可以先不做付费撤。
- 坝顶：存在负重撤离点。
- 管道区域：存在丢包撤离点。

高价值区域包括：

- 行政楼西楼
- 行政楼东楼
- 水泥厂
- 主变电站
- 游客中心
- 军营

这些高价值区域不需要钥匙或工具才能进入。地点内部未来可以存在需要特定钥匙进入的房间，但房间与地点本身是两层概念：玩家可以进入地点，不代表可以进入地点内所有房间。

第一版先不做钥匙房间。高价值区域通过更多高价值容器，以及开局时按照一定规律额外刷新高价值容器来体现收益差异。

额外高价值容器类型暂定：

- 小保险
- 大保险
- 骇客电脑

### 5.2 待确认

已确认：

- 第一张地图按“零号大坝”布局参考设计。
- 地点按上方列表执行。
- 地图有明确高价值区域。
- 高价值区域本身不需要钥匙或工具进入。
- 地点中未来可包含钥匙房间，但第一版先不做。
- 地图使用拓扑关系图，只能前往相邻区域。
- 第一版相邻移动耗时相同。

待确认：

- 每个地点的固定容器列表。
- 高价值区域额外容器的刷新规律，例如每局固定数量、按权重刷新，还是按区域独立概率刷新。
- 坝顶负重撤、管道区域丢包撤的具体规则。

### 5.3 拓扑关系草案

第一版拓扑以“可玩优先”为目标：西部与东部撤离点形成横向主线，中部行政楼、坝体内部和坝顶形成高风险交通枢纽，河滩与管道区域提供偏边缘路线。

相邻关系暂定如下：

```text
西部撤离点 -> 水泥厂 / 建筑工地 / 河滩
水泥厂 -> 西部撤离点 / 建筑工地 / 军营 / 行政楼西楼
建筑工地 -> 西部撤离点 / 水泥厂 / 集装箱 / 军营
军营 -> 水泥厂 / 建筑工地 / 行政楼西楼 / 集装箱
河滩 -> 西部撤离点 / 行政楼西楼 / 管道区域

行政楼西楼 -> 水泥厂 / 军营 / 河滩 / 行政楼东楼 / 坝体内部
行政楼东楼 -> 行政楼西楼 / 停车场 / 主变电站 / 坝体内部
集装箱 -> 建筑工地 / 军营 / 停车场 / 备用变电站
坝体内部 -> 行政楼西楼 / 行政楼东楼 / 坝顶 / 管道区域

停车场 -> 行政楼东楼 / 集装箱 / 游客中心 / 东部撤离点
坝顶 -> 坝体内部 / 主变电站 / 养护站
养护站 -> 坝顶 / 主变电站 / 游客中心
主变电站 -> 行政楼东楼 / 坝顶 / 养护站 / 备用变电站
备用变电站 -> 集装箱 / 主变电站 / 游客中心
游客中心 -> 停车场 / 养护站 / 备用变电站 / 东部撤离点

东部撤离点 -> 停车场 / 游客中心
管道区域 -> 河滩 / 坝体内部
```

设计意图：

- 西部撤离点附近连接水泥厂、建筑工地与河滩，形成开局三选一。
- 行政楼西楼、行政楼东楼、坝体内部是中部高风险交汇区。
- 集装箱、停车场、备用变电站形成偏外侧的中风险路线。
- 坝顶连接坝体内部、主变电站和养护站，适合作为风险较高但路线效率较好的上层通道。
- 管道区域只连接河滩与坝体内部，适合作为偏隐蔽路线和丢包撤离点所在区域。

## 6. 搜索系统

### 6.1 当前建议

每个区域拥有固定容器。战局生成时，每个容器生成并锁定内容；玩家搜索后，该容器标记为已搜索。

容器类型可包括：

- 工具箱
- 医疗包
- 武器箱
- 文件柜
- 保险箱
- 遗留背包

搜索不会实际消耗回合时间，但会进入一个专门的搜索界面，通过逐渐揭示道具来模拟原型游戏中“摸容器”的期待感。

打开容器时，容器内所有物品都会出现，但初始处于未揭示状态。未揭示物品先显示占用格子大小或轮廓，不显示具体名称、品质和价值。随后物品会逐个完成搜索揭示，显示图标、名称、品质、价值和可拿取状态。

搜索系统不设置快速搜索/仔细搜索的翻找程度差异。玩家打开容器后，就能看到该容器内所有物品的位置和大小，只是需要等待逐步揭示具体内容。

不同容器需要有明确的预期产物类型，让玩家能通过容器选择形成路线判断。例如：

- 武器箱：武器、配件、弹药
- 医疗包：药品、绷带、急救用品
- 工具箱：工具、零件、材料
- 文件柜：文件、现金、小型贵重物
- 保险箱：高价值物、小型稀有物
- 骇客电脑：电子设备、数据类物品、高价值小件

特战干员也会搜索容器。其搜索行为不一定完全清空容器，可能优先拿走高价值物、武器、药品或适合自身背包空间的物品，从而留下低价值物或塞不下的物品。玩家之后搜索该容器时，可以看到被翻找后的剩余内容。

### 6.2 待确认

已确认：

- 搜索不会实际消耗回合时间。
- 搜索会进入专门界面，并通过逐渐揭示物品制造期待感。
- 不存在快速搜索/仔细搜索。
- 打开容器后会显示所有物品，但未揭示时只显示大小或轮廓。
- 物品会在搜索过程中逐渐揭示。
- 特战干员搜索后可能留下低价值物。
- 容器有明确预期产物类型。

待确认：

- 搜索揭示速度是否与角色状态、装备或容器类型有关？
- 玩家是否可以在物品未完全揭示前提前关闭容器界面？
- 已搜索容器是否允许重复打开查看剩余物品？
- 第一版是否加入上锁容器，还是随钥匙房间一起延后？

## 7. 战斗系统

### 7.1 当前建议

初版采用简化回合制自动战斗。玩家遭遇敌人后，先选择逃跑或交战。

选择逃跑：

- 立即进行逃跑判定。
- 逃跑可能成功，也可能受伤，极端情况下可能直接死亡。
- 逃跑风险受敌人类型、敌人数量、玩家负重、玩家状态、地形等因素影响。

选择交战：

- 进入回合制自动战斗。
- 玩家不需要每回合手动选择行动。
- 双方按照武器、护甲、命中、伤害、状态等数值自动交火。
- 敌人血量显示为具体数值。
- 战斗会持续到一方死亡为止。
- 第一版不做交战中撤退，未来可扩展。

失败结果：

- 玩家战斗失败即直接死亡。
- 死亡后普通装备、背包和战利品全部丢失，保险格物品保留。

胜利结果：

- 敌人死亡。
- 若击败特战干员，玩家可以搜刮其装备和其本局搜到的物资。
- 若击败人机，玩家可搜刮其掉落物或驻守区域奖励，具体由敌人配置决定。

### 7.2 待确认

已确认：

- 遭遇敌人后，玩家可以选择逃跑或交战。
- 逃跑有可能受伤，甚至死亡。
- 交战采用回合制自动战斗。
- 敌人血量显示具体数值。
- 战斗会持续到一方死亡。
- 第一版不做交战中撤退。
- 战斗失败玩家直接死亡。

待确认：

## 8. 随机事件

### 8.1 当前建议

随机事件不是纯提示，而是改变当前战局选择。事件可发生在移动后、搜索后、战斗后、时间推进后或携带高价值物品后。

事件类型可包括：

- 听见脚步
- 远处交火
- 遭遇伏击
- 发现隐藏容器
- 撤离点异常
- 门锁/障碍
- 临时交易
- 负面状态

随机事件分为玩家可感知事件与后台不可感知事件。

玩家可感知事件会以文本、提示或状态变化呈现给玩家，例如听到脚步、远处交火、搜索中被攻击、发现隐藏物、脚滑受伤等。

后台不可感知事件只更新战局状态，不一定通知玩家。例如某个特战干员在另一区域被人机击败、某个容器被特战干员搜过、某个敌人移动到相邻地点。这类事件用于让战局像一个持续运行的小沙盘，而不是只围着玩家刷新。

事件会在玩家行动后按概率触发。行动包括移动、搜索、战斗结束、治疗、撤离尝试等。

到达区域并不等于立刻战斗。即使当前区域存在敌人，玩家也可能暂时没有遭遇，只是在后续搜索或事件判定中逐步触发风险。如果区域内存在敌人，可能出现“听到细微脚步”“远处有装备摩擦声”等提示事件。玩家继续搜索时，可能触发遭遇、被小兵打中或进入交战选择。

负面小事件需要满足合理先决条件。例如：

- 搜索过程中被小兵打中：要求当前区域仍存在人机或敌对单位。
- 听到脚步：要求当前区域或相邻区域存在敌人。
- 容器已经被翻过：要求该容器此前被特战干员搜索过。
- 搜索过程中脚滑摔断腿：不要求敌人存在，但应是低概率事件。

事件文本风格可以更幽默，但不直接照搬任何现有游戏的原文。幽默方向以轻微吐槽、反差和玩家熟悉的搜刮体验为主，例如“你郑重打开保险箱，里面的东西像是在郑重拒绝你”这类表达。

### 8.2 待确认

已确认：

- 随机事件可以真实改变地图状态。
- 事件文本可以更幽默，让玩家会心一笑。
- 事件在玩家行动后按概率触发。
- 存在玩家不可感知的后台事件。
- 玩家到达有敌人的区域后，不一定立刻战斗。
- 有敌人存在时，可以先触发脚步、声音等提示事件。
- 搜索过程中可能触发遭遇或负面事件。
- 负面小事件需要有合理先决条件。
- 可以存在搜索过程中脚滑摔断腿等非战斗负面事件。

待确认：

- 玩家可感知事件与后台事件的触发频率。
- 听到脚步类提示是否需要区分“本区域敌人”和“相邻区域敌人”。
- 负面事件是否会造成具体异常状态，例如出血、骨折、疼痛。
- 随机事件是否需要按地图地点或地点类型分池。

## 9. 撤离与结算

### 9.1 当前建议

撤离点分为普通撤离点、条件撤离点、高风险撤离点与一次性撤离点。

成功撤离后：

- 带出背包与装备中的物品
- 更新仓库
- 结算金钱、经验、任务进度

阵亡后：

- 丢失战局内大部分物品
- 装备可能损坏或丢失
- 若有保险格，则保留保险格物品

第一版撤离点规则：

- 西部撤离点：普通撤离。玩家到达后，消耗一个行动回合完成撤离。
- 东部撤离点：普通撤离。玩家到达后，消耗一个行动回合完成撤离。
- 坝顶：负重撤。玩家负重不超过 30kg 时，可以消耗一个行动回合完成撤离。
- 管道区域：丢包撤。玩家可以消耗一个行动回合完成撤离，但撤离时背包物品全部丢失，只保留身上装备与保险格物品。
- 河滩：未来可做付费撤，第一版暂不实现。

撤离成功后，玩家身上装备会全部带回。背包内物品根据撤离类型结算：普通撤离和负重撤可带回背包物品；丢包撤会丢失背包物品。

结算界面第一版展示：

- 本局带出价值
- 击败敌人数量

- 撤离成功后装备全部带回。
- 结算显示带出价值和击败敌人数量。

待确认：

- 撤离行动回合期间是否可能触发随机事件或遭遇。

## 12. 背包与物品占格规则

### 12.1 当前建议

背包管理是本游戏最重要的还原体验之一。第一版采用二维格子系统，玩家需要在战局中手动摆放战利品，在有限空间内决定带走什么、丢掉什么、放进保险格什么。

仓库初版不做格子限制，避免局外整理负担过重。格子压力主要存在于：

- 背包
- 胸挂
- 保险格
- 搜索容器界面
- 敌人尸体 loot 界面

### 12.2 容器与携带空间

玩家行前携带的背包决定主要战利品空间。不同背包拥有不同格子尺寸，例如：

```text
轻型背包：4x4
标准背包：5x5
战术背包：6x5
大型背包：6x6
```

胸挂提供较小但更偏战斗用途的空间，例如：

```text
简易胸挂：2x3
标准胸挂：3x3
战术胸挂：4x3
```

保险格固定为 3x3。保险格内物品在阵亡后保留。

### 12.3 物品尺寸

物品拥有宽高尺寸，并占用对应格子。初版建议使用较少尺寸，降低手机端操作复杂度：

```text
1x1：现金、小电子件、药片、小材料
1x2：弹匣、绷带、小工具
2x1：短配件、文件包
2x2：急救包、小保险价值物、头盔
1x3：枪管、长条工具
2x3：护甲、小型武器
2x4：步枪、长武器
3x3：大型装备或高价值大件
```

物品支持旋转。旋转用于解决“差一点塞进去”的整理乐趣，但 UI 需要提供明确按钮，避免手机拖拽过难。

第一版所有物品都允许旋转。

弹药允许堆叠。游戏内第一版不设置现金物品，货币作为局外数值存在，不占用背包格。

### 12.4 背包操作

第一版需要支持：

- 拖拽物品
- 点击选中物品
- 旋转物品
- 放入背包
- 放入保险格
- 放入胸挂
- 丢弃物品
- 从容器拿取物品
- 从敌人尸体拿取物品
- 一键整理

一键整理需要作为第一版功能实现，用于降低手机端整理负担。但手动摆放仍然是核心体验，一键整理只提供基础排列，不保证最优解。

可选但不强制第一版实现：

- 快速放入
- 物品锁定

### 12.5 搜索界面与背包的关系

搜索容器时，容器内物品以格子布局出现。未揭示物品只显示占格大小或轮廓，揭示后显示具体信息。

玩家可以在搜索界面中将已揭示物品拖入背包、胸挂或保险格。未揭示物品原则上不能拿取，需要等待揭示完成后才能操作。

如果背包空间不足，玩家需要：

- 旋转物品
- 调整已有物品位置
- 丢弃低价值物
- 放入保险格
- 放弃拿取

胸挂可以放任意小件物品，不限制为药品、弹药或投掷物。

保险格限制物品类型。保险格不能放入枪、防具、胸挂和背包。保险格主要用于存放高价值小件、材料、弹药、小型消耗品等。

已装备的武器、防具、胸挂和背包不占用背包格。只有脱下或作为战利品携带时，才需要占用背包格。

### 12.6 重量与格子的关系

格子决定“放不放得下”，重量决定“带不带得动”。两者同时存在。

重量影响：

- 是否满足坝顶负重撤条件
- 逃跑成功率
- 部分负面事件概率

第一版负重阈值：

- 坝顶负重撤：总负重不超过 30kg。

### 12.7 已确认

- 背包格子有限，需要花心思摆放。
- 物品需要占用格子，尽量还原同类游戏的整理体验。
- 所有物品允许旋转。
- 弹药允许堆叠。
- 游戏内第一版不设置现金物品。
- 仓库初版无限制。
- 保险格为 3x3。
- 保险格不能放枪、防具、胸挂和背包。
- 胸挂可以放任意小件。
- 第一版需要一键整理。
- 已装备的武器、防具、胸挂和背包不占用背包格，脱下或作为战利品携带时才占格。
- 管道区域丢包撤会丢失背包物品，只保留身上装备和保险格。

## 13. 装备耐久规则

### 13.1 当前建议

装备耐久只用于防护类装备。第一版中武器、胸挂和背包没有耐久。

拥有耐久的装备：

- 头盔
- 护甲

不拥有耐久的装备：

- 武器
- 胸挂
- 背包
- 消耗品
- 普通战利品

### 13.2 耐久损耗

交战中，头盔和护甲可能因承受伤害而损失耐久。耐久损失用于表现“这次虽然活下来了，但甲被打烂了”的战斗代价。

耐久损耗可以先采用简单规则：

- 玩家受到命中时，优先根据命中部位或简化概率判断是否由头盔/护甲吸收。
- 防具吸收伤害后，按固定比例损失耐久。
- 第一版不做过细的材质、穿透等级和弹种模拟。

### 13.3 耐久效果

防护装备有当前耐久和耐久上限。

```text
当前耐久 / 耐久上限
```

当防护装备当前耐久为 0 时，该装备不再提供防护效果。它仍然可以作为物品存在和带回，但需要维修后才有防护价值。

### 13.4 维修规则

玩家可以在特勤处维修防护装备。

维修规则：

- 维修消耗货币。
- 第一版维修费用先使用固定比例计算。
- 维修会恢复当前耐久。
- 维修会导致耐久上限下降。

示例：

```text
护甲：12 / 40
维修后：36 / 36
```

这里表示维修把当前耐久恢复到新的上限，但装备最大耐久从 40 下降到 36。

### 13.5 已确认

- 武器没有耐久。
- 胸挂和背包没有耐久。
- 耐久为 0 时，防护装备不再提供防护效果。
- 允许在特勤处维修装备。
- 维修会导致耐久上限下降。
- 维修费用第一版先用固定比例。

### 13.6 待确认

- 头盔和护甲是否都使用同一套耐久损耗比例？
- 维修后耐久上限下降比例是多少，例如每次维修下降 10%？
- 耐久上限下降到某个阈值后，是否禁止继续维修？
- 是否允许出售 0 耐久或低耐久防具？

## 14. 人机与特战干员行为规则

### 14.1 当前建议

敌人分为人机与特战干员两类。

人机负责提供区域风险与基础战斗压力。特战干员负责模拟同局竞争者，让地图在玩家看不见的地方也会发生变化。

### 14.2 人机

人机是地图中的基础敌对单位。

第一版人机行为建议：

- 开局生成在指定地点或按地点权重生成。
- 主要驻守所在区域。
- 不主动搜索容器。
- 可以与玩家遭遇。
- 可以与特战干员交战。
- 第一版固定驻守，不主动移动。

人机用途：

- 让高价值区域有更高进入风险。
- 作为搜索过程中的潜在威胁。
- 让特战干员可能在后台受伤或死亡。

### 14.3 特战干员

特战干员是模拟其他玩家或高威胁竞争者的敌人。

特战干员在开局时生成，并拥有自己的状态：

- 名称或代号
- 当前地点
- 生命值
- 装备
- 背包
- 已搜索容器
- 当前目标倾向
- 是否存活
- 是否已撤离

第一版每局生成 6 个特战干员。

特战干员会在后台行动。每当玩家执行行动并推进战局时，系统可以为存活的特战干员执行若干后台决策。

特战干员可执行的行为：

- 移动到相邻区域
- 搜索当前区域容器
- 拿走容器中的部分物品
- 与人机交战
- 与其他特战干员交战
- 与玩家遭遇
- 前往撤离点
- 成功撤离并离开战局

特战干员会主动撤离。当特战干员成功撤离后，其携带物资从本局永久消失，玩家无法再获得。

特战干员分装备档次。第一版可先使用三个档次：

- 穷装：低级武器、少量补给、小背包，战斗威胁较低，搜到好东西后更倾向撤离。
- 普通：标准武器、基础防护、常规背包，作为主要竞争者。
- 肥肥：更好武器与防具、更大背包，威胁高，但击败后收益也高。

### 14.4 特战干员搜索规则

特战干员搜索容器时，不一定清空容器。

其拿取逻辑可按优先级处理：

1. 高价值小件
2. 药品
3. 武器或配件
4. 弹药
5. 高价值大件
6. 其他能塞进背包的物品

如果特战干员背包空间不足，可能留下低价值物、体积过大的物品或不符合其倾向的物品。

被特战干员搜索过的容器需要保存状态：

- 未搜索
- 部分搜索
- 已搜索
- 剩余物品列表

玩家之后打开该容器时，只能看到剩余物品，不能重复获得已被拿走的物品。

### 14.5 特战干员目标倾向

为了让特战干员行为更自然，第一版可以给每个特战干员一个简单倾向：

- 搜刮型：优先前往高价值区域和容器多的地点。
- 保守型：搜索中低风险区域，拿到一定价值后倾向撤离。
- 战斗型：更容易前往有交火或高风险地点。
- 路过型：沿预设路线移动，偶尔搜索。

倾向不需要让玩家直接看到，但可以影响后台决策。

### 14.6 遭遇与可感知信息

玩家进入有敌人的区域后，不一定立刻遭遇。敌人存在会提高相关事件概率，例如：

- 听到细微脚步
- 远处传来拉栓声
- 发现刚被翻乱的箱子
- 听到短促交火

当遭遇触发时，玩家选择逃跑或交战。

### 14.7 击败与掉落

击败人机后，玩家可以获得其配置掉落。

击败特战干员后，玩家可以搜索：

- 其原本携带的装备
- 其背包中的物品
- 其本局从容器中搜到的物资

特战干员死亡后，其状态从地图活动单位变为可 loot 尸体。尸体所在区域需要保存，避免重复生成或重复掉落。

### 14.8 已确认

- 敌人分为人机和特战干员。
- 第一版人机固定驻守，不主动移动。
- 第一版每局生成 6 个特战干员。
- 特战干员会移动。
- 特战干员会搜索容器。
- 特战干员会主动撤离。
- 特战干员撤离后，其携带物资从本局永久消失。
- 特战干员分装备档次。
- 特战干员可能被人机击败。
- 玩家击败特战干员后可以 loot 其装备和搜到的物资。
- 敌人数量在开局时确定，不会无限刷新。
- 玩家不能看到当前剩余敌人数量。

### 14.9 待确认

## 16. 容器出货倾向草案

### 16.1 设计原则

容器出货不需要完全照搬原型游戏，但需要有明显的直觉和梗感：

- 医疗容器应该能出医疗用品，并低概率出“复苏呼吸机”这类大医疗高价值。
- 鸟窝、窨井盖这类彩蛋容器应该能出离谱小贵重物，例如非洲之心。
- 武器类容器应该稳定出武器、配件、弹药，偶尔出防具。
- 行李、衣服、快递盒更偏杂物和小贵重，偶尔给玩家惊喜。
- 电子类容器更偏芯片、数据、显卡、服务器部件等。
- 水泥车、工具柜更偏工具材料，也可以少量出很奇怪的工业大件。

## 18. 当前第一版范围修订

### 18.1 修订说明

本章覆盖前文中关于完整交战、装备耐久、特战干员后台模拟、复杂医疗与完整装备经济的第一版实现范围。

前文相关设计暂时保留为后续扩展方向，但当前第一版只实现：

- 地点移动
- 容器搜索
- 搜索揭示
- 随机事件
- 生命值
- 三种负面效果
- 三种功能道具
- 简单撤离与结算

第一版不实现：

- 完整回合制交战
- 特战干员后台移动与搜索
- 击败敌人后的尸体 loot
- 装备耐久与维修
- 复杂武器、防具、胸挂、背包经济
- 任务系统
- 角色等级

### 18.2 核心玩法

当前第一版的核心流程为：

```text
特勤处简易准备 -> 进入地图 -> 相邻地点移动 -> 搜索容器 -> 触发随机事件 -> 处理生命值/负面效果 -> 继续搜索或撤离 -> 结算
```

游戏重点是先验证：

- 地图节点移动是否顺手。
- 地点容器配置是否有探索感。
- 搜索揭示是否有期待感。
- 随机事件是否能制造轻量搜打撤味道。
- 负面状态和医疗道具是否形成简单取舍。

### 18.3 交战的第一版替代方案

第一版不做战斗界面和自动战斗。

交战通过随机事件实现。例如玩家移动或搜索后，可能触发：

- 遭遇小兵，并成功击败，无伤。
- 遭遇小兵，击败但损失生命值。
- 遭遇小兵，被一个肘击打到骨折。
- 搜索时被冷枪击中，获得伤口。
- 脚下打滑，腿骨折。

事件可以有结果文本，但不进入单独交战流程。

### 18.4 生命值

玩家拥有生命值，第一版建议最大生命值为 100。

生命值变化来源：

- 随机事件造成伤害。
- 伤口随时间流逝造成伤害。
- 强效注射剂恢复生命值。

生命值降至 0 时，玩家死亡并进入失败结算。

单局总时间为 30 分钟。

### 18.5 负面效果

第一版只做三种负面效果：

```text
腿骨折
手骨折
伤口
```

负面效果规则：

- 腿骨折：影响移动消耗的时间。
- 手骨折：影响搜索速度。
- 伤口：随时间流逝损失生命值。

负面效果可以同时存在，也可以重复叠加记录。但同类负面效果的实际影响不叠加，例如多个手骨折与一层手骨折的搜索惩罚相同。

### 18.6 时间影响

当前第一版仍使用回合制行动时间。

基础规则：

- 移动到相邻地点默认消耗 2 分钟。
- 每次搜索行动消耗 1 分钟。
- 玩家从当前地点未搜索容器列表中指定一个容器进行搜索。
- 容器被搜索一次后标记为已搜索，不能再次出货。
- 搜索行动后进入该容器的详细物资揭示界面。
- 撤离消耗一个行动回合。

腿骨折影响移动：

- 正常移动：消耗 2 分钟。
- 腿骨折移动：消耗 3 分钟。

手骨折影响搜索：

- 正常搜索：按标准速度逐步揭示物品。
- 手骨折搜索：搜索耗时延长 50%。

物资揭示速度与物品稀有度有关：

```text
白色：0.5 秒
绿色：1 秒
蓝色：1.5 秒
紫色：2 秒
金色：3 秒
红色：4 秒
```

伤口影响时间流逝：

- 每经过 1 分钟，损失 30 点生命值。
- 伤口流血不会直接致死，生命值最低降到 1。

### 18.7 功能道具

第一版只做三个功能道具：

```text
强效注射剂
快拆手术包
瓶装止痛药
```

强效注射剂：

- 用途：恢复生命值。
- 每根恢复量：60 点生命值。
- 可以分次使用，每根累计最多恢复 60 点生命值。
- 不能超过生命值上限。
- 尺寸：1x1。
- 默认携带数量：4 根。

快拆手术包：

- 用途：治疗负面效果。
- 使用次数：4 次。
- 每次使用可以移除 1 个负面效果。
- 可治疗腿骨折、手骨折、伤口。
- 尺寸：1x2。
- 默认携带数量：1 个。

瓶装止痛药：

- 用途：在一定时间内临时压制骨折效果。
- 压制范围：腿骨折、手骨折。
- 不压制伤口。
- 生效期间，已有腿骨折和手骨折暂时不产生移动/搜索惩罚；若期间新增骨折，也在持续时间内被压制。
- 随机事件仍可造成生命值伤害和伤口。
- 持续时间：5 分钟。
- 使用次数：3 次。
- 尺寸：1x1。
- 默认携带数量：1 瓶。

### 18.8 随机事件要求

随机事件需要支持先决条件。

示例：

- 遭遇小兵：需要当前地点配置有小兵风险，或事件池允许战斗类事件。
- 被小兵打中：需要当前地点仍存在小兵风险。
- 脚滑摔断腿：不需要敌人存在，低概率触发。
- 翻箱划伤形成伤口：搜索类事件，可低概率触发。
- 手骨折：可来自搏斗、跌落、重物砸手等事件。

第一版不按地点风险分低、中、高三档。随机事件先只在搜索行动后触发，触发概率约为 10%。负面交战结果完全由“遭遇小兵”这一类随机事件触发。

遭遇小兵事件结果表：

```text
40%：成功击败小兵，无伤。
25%：成功击败小兵，损失生命值。
15%：成功击败小兵，但腿骨折。
10%：成功击败小兵，但手骨折。
10%：成功击败小兵，但获得伤口。
```
